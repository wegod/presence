## 2. Backlog 项

### B1. Kafka 软降级（短暂抖动不拒单）

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG` |
| 描述 | Kafka 短暂不可用时，下单仍接受：只写订单+Outbox，不触发全局停秒杀；靠 Outbox 缓冲发送 |
| 与 MVP 差异 | MVP：**Kafka 不可用 → 熔断停秒杀** |
| 依赖 | 积压监控、发送 lag 告警、必要时限流加严 |
| 风险 | Redis 预扣长期无法落到 MySQL，占用与对账窗口变长 |

### B2. 停售巡检 Job

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG` |
| 描述 | 定时扫描 DB `available_stock=0` 或异常仍可售的 SKU，强制 `sale_enabled=0` 并同步 Redis |
| 与 MVP 差异 | MVP：仅事件驱动停售，**无巡检 Job** |
| 价值 | 兜底漏事件、人工误开 |

### B3. 依赖熔断半开自动恢复与流量回补

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG` |
| 描述 | Resilience4j half-open 探测成功后自动恢复接单；可选逐步放量 |
| 与 MVP 差异 | MVP 可手工/配置复位；不要求精细半开运营策略 |

### B4. 库存分桶（Sharding / Buckets）

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG` |
| 描述 | 单 SKU 库存拆多 Redis key / 多行，降低热点 |
| 前提 | 库存与并发显著高于 MVP（>1000 或热点更剧烈） |

### B5. 活动进行中调整库存

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG` |
| 描述 | 运营在活动中增/减库存；需版本令牌、禁止覆盖预扣、审计 |
| 与 MVP 差异 | MVP：**禁止**进行中改库存 |

### B6. 背压与可观测性

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG` |
| 描述 | Outbox lag、Kafka consumer lag、Lua 失败率、熔断状态大盘；与限流联动背压 |
| 产出 | Metrics / Grafana 或等价 |

### B7. 完整支付对账报表

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG` |
| 描述 | 日终对账：订单 PAID vs 支付成功单、长短款报表、人工调账流 |
| 与 MVP 差异 | MVP：mock 支付 + 查单补偿 + 超时取消 |

### B8. 真实登录与支付

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG` |
| 描述 | OAuth/会话体系；对接真实支付渠道与签名验签 |
| 与 MVP 差异 | Cookie 随机 userId；mock pay/callback |

### B9. 多机 / 高可用部署

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG` |
| 描述 | App 多副本、Kafka 多 broker、Redis HA、MySQL 主从；分布式锁与 Job 分片 |
| 与 MVP 差异 | 单机 Docker 2C6G |

### B10. 去掉 Kafka 的同步扣减模式（对照实验）

| 字段 | 内容 |
|------|------|
| 状态 | `BACKLOG`（仅实验，非默认） |
| 描述 | 配置开关：下单事务内直接扣 MySQL，跳过 Kafka |
| 说明 | MVP ADR 已否决作为默认架构；仅可作为性能对照分支 |

## 3. MVP 已包含（勿重复进 Backlog）

- Redis Lua 预扣 + MySQL 真相源
- Outbox + Kafka（3 partitions）+ 手工 ACK
- Redis/MySQL/**Kafka 熔断停秒杀**
- 预热（warmup_token，开抢不覆盖）
- Outbox / Redis 补偿 / 订单超时对账
- 模拟支付与回调幂等
- Sentinel 限流 + 最多 10 轮压测调参
- Cookie 登录；库存 ≤1000；进行中不改库存
